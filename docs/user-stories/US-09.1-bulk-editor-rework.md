# US-09.1 — Bulk editor rework: slim grid, folder truncation, split Edit & Compare screen

| Field      | Value                                             |
| ---------- | ------------------------------------------------- |
| Milestone  | M3 Edit                                           |
| Depends on | US-09                                             |
| State      | tracked in [feature-list.json](feature-list.json) |

## User story

As a QA engineer, I want a slimmer grid with a width-limited Folder column and a split Edit & Compare screen, so that I can edit Gherkin while seeing live changes against the Xray version, without any remote write.

## Context

Rework of [US-09](US-09-bulk-editor-grid.md). US-09 must be `passing` before this story starts. After US-09 three problems remain:

1. Two grid columns (Labels, Status) add noise, storage and code.
2. The Folder column takes too much width, leaving little room for the Gherkin preview.
3. Gherkin cannot be edited in the grid. Users need a dedicated place to edit Gherkin and see changes against Xray as they type.

Edits remain **local drafts only**. Nothing is written to Xray or Jira in this story (US-18/19).

**Assumption to confirm before starting:** the two removed columns are **Labels** and **Status**. If other columns are meant, only the requirement table below changes. Folder, Gherkin preview and the Draft indicator are kept.

**Open questions**

1. Confirm the two removed columns are Labels and Status.
2. Should "Edit all" also be available from the Draft filter (open all existing drafts)? Not required here.
3. Should find & replace in [US-10](US-10-bulk-actions.md) also act on Gherkin text, or only on summary?

## Scope — In / Out

**In**

- Remove the Labels and Status columns from UI, API, database, types, validation, fixtures and tests.
- Folder column: fixed, limited width; trimmed value; full value in an accessible tooltip.
- Gherkin column takes the remaining width (read-only preview only).
- Selection, then **Edit all** button, opens the Edit & Compare screen with live diff and autosaved drafts.

**Out**

- Gherkin highlighting, completion and parser linting (US-12).
- Conflict resolution when the remote changed (US-17).
- Any write to Xray or Jira (US-18/19). This story creates local drafts only.

## Technical notes

### Removal of Labels and Status (all layers)

| Layer       | Change                                                                                                                                                                                                                                       |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| UI          | Remove both columns, cells, header sort/filter and inline editors. No replacement controls.                                                                                                                                                  |
| API         | Draft endpoints accept only `summary` and `gherkin`. Requests containing `labels` or `status` return `400` (`unknown_field`).                                                                                                                |
| DB          | Forward-only migration: (a) delete drafts whose only differences were labels/status; (b) strip the two fields from remaining drafts; (c) drop the columns from draft and snapshot/baseline tables. Log the number of drafts deleted/changed. |
| Fingerprint | Exclude labels/status. Bump the fingerprint version and recompute stored fingerprints from baseline data in the same migration, so existing drafts are not flagged stale.                                                                    |
| Code        | Remove from TypeScript types, schemas, `draft-rules`, stores/composables, mock Xray/Jira fixtures, seed data and docs. Remove the Xray/Jira requests that exist only to load them, where possible.                                           |
| Search      | Search covers key and summary only.                                                                                                                                                                                                          |

### Grid columns and widths

Final columns: **Select · Key · Summary · Folder · Gherkin · Draft**.

- Key: fixed (content width). Draft: fixed small indicator column.
- Summary: `min-width: 280px`, flexible. Long values stay in the input (no layout shift).
- Folder: `width: clamp(120px, 14%, 200px)`, single line, no wrapping.
- Gherkin: `flex: 1`, `min-width: 320px`. The existing Preview toggle stays; the expanded preview is read-only, monospaced, with a max height and its own scroll.
- No horizontal page scroll at 1280px viewport width or wider.

### Folder trimming and tooltip

- When the path does not fit, trim the start with an ellipsis and keep the leaf segment visible (`…/Brochures Industry Page`).
- Hover and keyboard focus show a tooltip with the full path: `role="tooltip"`, linked via `aria-describedby`. The cell is focusable with `tabindex="0"`. A bare `title` attribute is not sufficient.
- Short values show no tooltip.
- Tooltip text is selectable and copyable, and is rendered in a portal/teleport so the table's overflow container never clips it.

### Selection and "Edit all"

- Row checkboxes and a header select-all. With a filter or search active, select-all selects all matching tests, not only the rendered (virtualized) rows. Show "N selected".
- Selection is a set of keys, independent of virtualization, and is kept when scrolling or paging.
- **Edit all (N)** in the toolbar: disabled when N = 0; otherwise navigates to the Edit & Compare screen for exactly those tests.
- The selection is handed over through a client store mirrored to `sessionStorage` (not the URL, to avoid length limits). Route: `/tests/edit?project=<id>`. If the store is empty on load (for example, a new tab), redirect to the repository with a notice.
- The grid is not a place to edit Gherkin. No inline Gherkin editor is added there.

### Edit & Compare screen

Layout reference: a Git/VS Code side-by-side compare.

- **Left rail:** the selected tests (key, trimmed summary, draft dot, save-state icon). Click, or `Alt+↓/↑` to move between tests. Shows `i / N`.
- **Header:** key, **Summary** input (same rules as the grid), folder (trimmed, with tooltip), "Back to repository", save-state text.
- **Main:** two panes with synchronized scroll.
  - Left (read-only): Xray version, the baseline snapshot the draft is based on.
  - Right (editable): Draft, the working Gherkin.
- **Live diff:** line numbers on both sides; added and changed lines highlighted; hatched filler on the opposite side keeps lines aligned; change markers in the gutter; an overview ruler on the right edge; unchanged regions collapsible.
- **Per-change controls** in the center gutter: revert this change (left to right). Header buttons: **Revert test**, **Next change**, **Previous change**.
- Typing updates the diff in real time (debounced at most 150 ms; no visible lag for Gherkin up to 2,000 lines).
- Autosave: debounced draft save per test, using the same endpoint as US-09. Save state: `idle | saving | saved | error`, with retry on error and no lost keystrokes while a save is in flight.
- Setting the text back to the baseline removes the draft (US-09 no-op rule).
- Details for each test are fetched fresh on open and never cached client-side. Opening the editor creates or safely refreshes the snapshot and preserves the baseline of any changed draft (US-07 rule).
- Navigating away warns only if a save is in flight or has failed.
- Editor library: a diff-capable editor (Monaco Diff Editor or CodeMirror 6 merge view). Load it client-only and lazily on this route so it does not enter the grid bundle. Minimal Gherkin tokenization is optional; full Gherkin tooling is US-12.

### Non-functional

- Keyboard: every control is reachable. The diff editor does not trap focus (`Esc` then `Tab` leaves it). WCAG 2.1 AA in light and dark themes.
- No secrets or tokens in the browser. No remote writes.
- Works with 500 selected tests: the rail is virtualized, and only the active test's details are held in the editor.

### API contract (delta)

```ts
// Draft write (PATCH): labels and status removed
interface DraftPatch {
  summary?: string
  gherkin?: string | null
}

// Detail (GET /api/tests/by-key/:key): labels and status removed
interface TestDetail {
  key: string
  name: string
  folderPath: string
  testType: string
  gherkin: string | null
  readOnly: boolean
  base: { summary: string; gherkin: string | null } // snapshot baseline for compare
  draft: { summary?: string; gherkin?: string | null } | null
}
```

If no endpoint loads draft status for many keys at once, add `POST /api/drafts/lookup { keys: string[] }` returning `{ [key]: boolean }` for the rail indicators.
