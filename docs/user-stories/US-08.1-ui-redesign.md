# US-08.1 — XrayBulk UI redesign (design system, shell, and screens)

| Field      | Value                                             |

Design reference: [refer/template/index.html](../../refer/template/index.html) (visual and behavioral prototype, **not code to copy**) and [refer/template/UI-SPEC.md](../../refer/template/UI-SPEC.md) (implementation spec). Decisions: [ADR 0015](../decisions/0015-ui-design-system-and-routes.md).

## User story

As a QA engineer, I want the app to look and behave like the XrayBulk design — a clean shell, a landing page, a focused login, and a two-pane repository with light/dark themes — so that the tool is pleasant and predictable to use before the editing features land on top of it.

## Context

US-00 → US-08 shipped working but unstyled screens: `/` is a long workspace-setup form, `/repository` is a raw table plus a drawer, and `/editor` is a stub. The design in `refer/template` replaces that look and defines the page structure that US-09 → US-20 build on. Doing the visual foundation once, now, avoids restyling every later story.

This story is **presentation and navigation only**. It adds no editing, no drafts, no remote writes, and no new Jira/Xray calls. Features the template shows that belong to later stories are reserved, not built:

| Template element                                            | Built in    |
| ----------------------------------------------------------- | ----------- |
| Inline-editable summary/labels/status grid, warning dot     | US-09       |
| "N drafts" header chip, "Review N changes" button           | US-09/16    |
| Bulk bar actions (`+ Label`, `Set status…`, Find & replace) | US-10       |
| Gherkin code editor, validation strip, Compare with Xray    | US-11/12/15 |

The UI-SPEC text refers to `stories.json`; in this repo that file is [feature-list.json](feature-list.json). Its rules (WIP = 1, only `pnpm verify` sets `passing`) apply unchanged.

## Scope

**In**

_Design system_

- Design tokens as CSS variables in `app/assets/css/main.css`: `--bg --sf --ink --mute --line --brand --soft --ok --warn --bad --add --del --code` with the light values from UI-SPEC §1 and dark overrides, mapped onto the Nuxt UI theme (ADR 0002 stays; no second UI library). Dark mode uses Nuxt UI color mode (system default, user override persisted), see ADR 0015.
- Type: Inter/system sans, 14 px base; monospace for Gherkin. Radius 8 px controls, 12 px cards. Visible focus ring on every interactive element. Two-column layouts stack below 800 px.
- Shared building blocks used by every screen: `AppHeader`, `PageCard`, `StatusBadge`/`Chip`, `EmptyState`, `ErrorBanner`, `LoadingSkeleton` (each in `app/components/`).

_Shell (`AppHeader`, all pages)_

- Sticky top bar: logo (links to `/`), project key/name and "Repository" breadcrumb when signed in, theme toggle (`aria-label`), sign-out menu for signed-in users. The prototype's screen switcher is **not** implemented.
- Header reserves a slot for the US-09 draft-count chip (renders nothing now).

_Routes (ADR 0015)_

| Route                                | Screen                                                                                                      | Access                                                                  |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `/`                                  | Landing                                                                                                     | public                                                                  |
| `/login`                             | Login                                                                                                       | public; signed in → `/repository` (or `/settings` if project not ready) |
| `/settings`                          | Workspace setup: Jira connection, Xray credentials, project, folder pull (content of today's `/`, restyled) | required                                                                |
| `/repository?folder=<path>&q=<text>` | Repository                                                                                                  | required + project ready                                                |
| `/tests/:key`                        | Test case page (read-only in this story)                                                                    | required + project ready                                                |
| `/auth/jira/select-site`             | Site picker (restyled, same behavior)                                                                       | public flow step                                                        |

- Unauthenticated access to a protected route redirects to `/login?next=<path>`; after sign-in the user lands on `next`. `next` accepts only same-origin relative paths (open-redirect safe).
- Route guards cover `/repository`, `/tests/*`, and `/settings` on the server (today only `/` and APIs are guarded; `/repository` is not).
- Post-login destination: `next` if present, else `/repository`. A workspace without a ready project is then redirected to `/settings` by the existing readiness guard (no readiness lookup at login). `next` survives the OAuth round trip in a signed, short-lived cookie and is re-validated on use.
- API-token sign-in returns JSON `{ redirectTo }` (no 303); the login page navigates there.
- A signed-in user opening `/login` is redirected server-side to the validated `next` or `/repository`.
- Project-not-ready redirect from repository routes (`/repository`, `/tests/*`) goes to `/settings` (was `/`).
- The `/editor` stub is removed.

_Landing (`/`)_ — UI-SPEC §3

- Badge "Jira + Xray Cloud", H1, one-line subtitle, primary CTA "Sign in with Jira" → `/login` (signed-in users see "Open repository" or "Continue setup" instead; session is detected from `useUserSession().session.value.userId`, and `/api/auth/session` is fetched only when a session exists), workflow pills (Pull → Edit drafts → Import .md → Review diff → Sync → Export), six feature cards in a `minmax(230px, 1fr)` grid. Static content, no API calls. No "View demo" (there is no demo mode).

_Login (`/login`)_ — UI-SPEC §4

- Centered card (max 420 px) with tabs "Atlassian OAuth" (default) and "Email + API token".
- OAuth tab: full-width "Continue with Atlassian" (full-page navigation to the existing OAuth start route), helper text about encrypted tokens. Error banner for `?message=` values already produced by US-02.
- API-token tab: Jira site URL, Email, API token (`type=password`, `autocomplete="off"`). Client-side check for `https://<site>.atlassian.net` with inline error (server stays the authority and keeps SSRF protection). "Verify & connect" disabled until all fields are valid; spinner while pending; server errors mapped to inline messages; token cleared from state after submit.
- Tabs are keyboard operable (`role="tablist"`, arrow keys).

_Settings (`/settings`)_

- The existing onboarding checklist and forms (Jira connection, Xray credentials, project selection, folder pull) are regrouped into cards with the new look. Behavior, API calls, and copy required by US-02 → US-06 are unchanged.

_Repository (`/repository`)_ — UI-SPEC §5, limited to implemented data

- Two columns: 260 px folder sidebar + main; stacks below 800 px.
- Sidebar (`FolderTree`): "FOLDERS" label, "All tests" root, indented rows with test counts, selected row in `--soft`/`--brand`, keyboard navigation (arrows move, Enter selects, Left/Right collapse/expand), expansion remembered per workspace (existing US-08 behavior), "Pull from Xray" button with progress, disabled while a pull runs.
- Toolbar: search (key or summary, debounced, `?q=`), result count, "Include subfolders" toggle. Folder and search remain deep-linkable and back-button safe.
- Selection bar (visible when ≥ 1 row selected): "N selected", "Clear", and "Open in editor" (enabled when exactly one test is selected; runs the existing editor-selection call, then opens `/tests/:key`). Bulk actions are added to this bar by US-10.
- List (`TestList`): columns Select, Key (link to `/tests/:key`), Summary, Folder — the lightweight index fields only. Header checkbox selects all visible rows. Horizontal scroll inside the card on narrow screens. The template's footer note ("Edits are saved as local drafts…") is added by US-09, since nothing is editable yet.
- Loading skeleton, empty (never pulled → "Pull from Xray" CTA, empty folder, no search results), and error states.
- The US-08 detail drawer is replaced by the `/tests/:key` page.

_Test case page (`/tests/:key`)_ — UI-SPEC §6, read-only

- Two columns (300 px details card + flexible card), stacking on mobile. "← Back to repository" preserves `folder` and `q`.
- Details card: key, summary, status, labels as chips, type, "Open in Jira" link (existing safe URL rule). No inputs, no `Undo all` / `Add to review`.
- Gherkin card: title "Gherkin steps", syntax-highlighted read-only steps using the existing safe `GherkinCode` component (no `v-html`). Fresh Xray details fetched on each open and not persisted (US-08 rule unchanged).
- Loading, error, and unknown-key (404) states.

_Quality bars_

- WCAG 2.1 AA: labelled inputs, visible focus, `aria-label` on icon-only buttons, contrast ≥ 4.5:1 in both themes (primary button label color is chosen per theme to meet this), keyboard-operable tree and list.
- Existing e2e specs US-00 → US-08 are updated for the new routes; their behavioral assertions stay.

**Out**

- Drafts, inline editing, labels/status columns, draft dot, draft chip, "Review N changes" (US-09, US-16).
- Bulk actions (US-10), Gherkin editor and validation (US-11, US-12), diff view (US-15).
- Virtualized rows (US-09; the list stays server-paginated as in US-08).
- Landing "View demo" and any demo mode.
- New backend features other than key-based test lookup and route guards.

## Technical notes

- **Tokens ↔ Nuxt UI**: define the variables on `:root` and under `.dark`, then point Nuxt UI's semantic colors (`primary`, neutral scale, `--ui-bg`, `--ui-border`, …) at them in `app.config.ts` / `main.css` so built-in components (`UButton`, `UInput`, `USelect`, `UTabs`) inherit the look. Avoid per-component hex values.
- **Color mode**: Nuxt UI `useColorMode`. Do not add the prototype's `[data-theme]` attribute; if a stylesheet needs it, derive it from color mode.
- **Route guard**: replace the `pathname !== '/'` shortcut in `server/middleware/01.auth.ts` with an explicit protected-page list (`/settings`, `/repository`, `/tests/`); keep `/`, `/login`, and `/auth/*` public. Redirect target is `/login?next=<encoded path+query>`. Put `next` parsing in `shared/` as a pure `safeNextPath()` (relative path only, no `//`, no scheme, no backslash, length-capped) and unit test it.
- **Key lookup**: `/tests/:key` resolves the cached index entry by `key` scoped to workspace and project, then reuses the US-08 detail fetch. Add `GET /api/tests/by-key/:key` (or accept a key in the existing detail route) returning 404 for unknown keys. Keep the no-persist rule.
- **Folder query**: keep `folder=<path>` (US-08 deep-link contract) rather than the template's numeric `folder=:id`.
- **Landing is static** but renders a different CTA when a session exists. `useUserSession().loggedIn` is always false in this app (the session has no `user` field), so check `session.value.userId`; only then call `/api/auth/session`. Signed-out visits make no API call and log no 401.
- **`next` through OAuth**: `/auth/jira/login?next=` stores the validated path in a signed HttpOnly cookie; callback and site-selection use one `resolvePostLoginPath()`; API-token takes `next` in the body.
- **Detail service**: extract the Xray detail fetch/mapper duplicated in `tests/[testCaseId].get.ts` and `selection.post.ts` into a server service before adding the by-key route.
- **Mock write counter**: add `writeRequestCount` (+ reset) to `packages/mock-services` (non-GET Jira REST, GraphQL mutations; not OAuth token or Xray authenticate); the zero-writes done check asserts it.
- **Lint**: `vue/no-v-html` is only a warning today; raise it to `error`.
- **Pagination**: the list stays Previous/Next; select-all covers the visible page only.
- **e2e helpers**: add `e2e/support/` (`signIn`, `control`, `writeRequestCount`) and migrate touched specs to it.
- **Move, don't rewrite**: `app/pages/index.vue` (workspace setup) moves to `app/pages/settings.vue` and is split into cards/components; keep data-testids that existing specs rely on where sensible, and update specs where routes changed.
- **No new UI dependency**. A11y helpers: `@axe-core/playwright` is already installed.
- **Performance**: the existing 1,000-case query latency integration check must still pass; no new client-side data fetching on the landing page.
- **Specs to update for moved routes**: `e2e/us-00-smoke`, `us-02-oauth-sign-in`, `us-03-api-token-sign-in`, `us-04-xray-connection`, `us-05-project-selection`, `us-06-pull-folders`, `us-07-pull-tests`, `us-08-repository-browser`, and the redirect/location assertions in `tests/integration/auth-oauth.test.ts`, `jira-refresh.test.ts`, `project-selection.test.ts`, and `auth-api-token.test.ts` (public `/`, `/settings` redirect, JSON API-token response).

## Verification (layer 1 static → layer 2 runtime → layer 3 e2e)

1. Static: `pnpm check`
2. Runtime: `pnpm test:unit tests/unit/ui` (`safe-next-path`, API-token form validation), `pnpm test:int tests/integration/route-guards.test.ts` (public/protected pages, `next` redirect, key lookup 404/200), plus the existing US-02 → US-08 integration suites via `pnpm check`/`pnpm test:int`
3. End-to-end: `pnpm test:e2e e2e/us-08-1-ui-redesign.spec.ts`, then the full `pnpm test:e2e` as regression for the moved routes
